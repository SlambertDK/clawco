Security promise

In three sentences

Clawco's limits live in the code, not in a prompt: whatever a model says, Clawco will not pay, and will not write to other people or delete anything without your yes. What your sources give the agent (mail, invitations, messages, notes, feeds) is marked as data and never as an instruction, and a new rule always needs a tap from a person. A Clawco you install yourself keeps what it knows about you in your user folder and your notes folder on your own machine: export it as a zip, delete it with Slet alt or by removing the folders, and Clawco collects nothing about how you use it.

How it is enforced

Every action passes one decision step before anything runs. The kind of action comes from the app, never from the model, so what a model writes can add a refusal but cannot lift one.

A voice command cannot give a yes: writing to other people and deleting need a tap on a button on the screen, once, for that one thing. Paying and copying across zones are refused every time.

Every decision, including every refusal, is written to an audit log. What Clawco does through a button is written to the room's log, with the way to undo it when there is one. A stop button halts every running and queued agent run and keeps Clawco paused until the owner starts it again.

The refusals

  • Paying: refused every time.
  • Writing to other people: only with your tap on a button on the screen.
  • Deleting: only with your tap on a button on the screen.
  • Copying across zones: refused every time.

The trust ladder

Where the promise stops

  • The agent's own tools. If you use Hermes, its tools (a terminal, the web) are set by Hermes, not by Clawco. Clawco watches each run and stops it when a tool reaches for sending or deleting, but it cannot stop a tool before it starts. The built-in direct model agent has no tools.
  • Marking is a convention. A model can ignore that text is marked as data, and a fooled model can change what is written on a card. It cannot lift a limit, make a rule or press a button.
  • Your model provider sees what is sent to it. A model on your own machine keeps that step on your machine. Voice always goes through ElevenLabs.
  • A stolen laptop or a stolen device on your tailnet is a stolen account. There are no passwords on a tailnet install, and the data folder is not encrypted at rest.

The threat model

The rule behind it: no connection may hold all three of private data, text an outsider wrote and a way to talk to the outside, unless a control cuts one of them. Every connector has a row that says which one it cuts, and a test fails when a connector has no row.

The full document names the actors it assumes (a hostile sender, a hostile web page, a household member, a guest, a compromised model provider, a stolen device) and lists the risks that remain.

The threat model

How it is reached

By default Clawco listens on 127.0.0.1, the machine it runs on. You can add your own tailnet. Requests that arrive through Tailscale Funnel are refused.

Where your data lives

A Clawco you install yourself keeps your data in your user folder, on your machine.

When the agent works, the text it needs goes to the model you chose. A model on your own machine keeps that step on your machine.

What leaves your machine

These are all the outside addresses that appear in Clawco's code, and why. A test keeps this list equal to the code.

  • Your model provider, when Clawco calls it directly: it receives the text the agent works on. With a model on your own machine this does not happen.
  • Google, only if you connect Google Calendar or Gmail: sign-in, then reading your calendar or your mail envelopes.
  • ElevenLabs, only if you switch voice on: audio and the spoken overview go there through your Clawco, and the key never reaches the browser.
  • The voice library, loaded by your browser from this address, only on pages where voice conversation is on.
  • Google Fonts: your browser asks for the two typefaces every Clawco page uses, so Google sees that request. If it is blocked, the page uses system fonts.
  • Your mail server and the news feeds you added: Clawco connects to the addresses you gave it, and to none other.

What is collected

No usage statistics. This version of Clawco has no analytics and no code that reports how you use it to Clawco or to anyone else.

The one thing that can report is a technical error report. It is off unless the person running the install sets KC_FEJLRAPPORT_DSN, and it holds technical fields only: error type, file and line, version, route, status code and duration, never the content of your mail, notes or messages.

The tests behind the promise

  • test/graenser/afgoer.test.ts the decision step: each refusal and the yes
  • test/graenser/tegn.test.ts the one-time tap that stands for a yes
  • test/graenser/opsyn.test.ts watching the agent's own tools
  • test/graenser/redaktion.test.ts secrets masked in what is sent and shown
  • test/graenser/trusselsmodel.test.ts a connector without a threat-model row fails
  • test/tillid/trin.test.ts the trust ladder and its limits
